# ODOSv5 Scene Page Contracts

Scene pages must function as DM control panels.

They should not be mostly art.

## Required scene boxes

Each single-scene core page should include at least 8 named content boxes:

1. Purpose
2. What the Characters See
3. Read-Aloud
4. Key Checks
5. Clues
6. Secrets
7. Trap / Puzzle / Hazard / Combat
8. Point Forward
9. Fail Forward
10. Handouts
11. Escalation
12. Innkeeper's Tip
13. Monster's Mischief, if applicable

## Setting art ratio

- Setting image should use 30-38% of the page.
- DM-facing text and mechanics should use 60-65% of the page.
- Do not allow setting art to consume half or more of a scene page unless the page is an appendix art page.

## Key check format

Each key check should include:
- ability / skill
- DC
- success result
- failure cost or complication

Example:

```text
Acrobatics DC 13: cross the broken gap safely; fail costs time or separates a hero.
Perception DC 12: spot scouts above; fail gives raiders advantage on first action.
Investigation DC 13: read sabotage marks; success reveals the bell sled route.
Survival DC 14: track Brindle; success finds the safer upper path.
```

Use 4-6 key checks for a single-scene page.

## Trap / Puzzle / Hazard / Combat format

Every trap, puzzle, hazard, or combat box should include:
- trigger or setup
- DCs
- success result
- failure consequence
- how to bypass, solve, soften, or exploit it

If the scene has no formal trap or puzzle, include `Scene Pressure` with:
- what changes if players wait
- what enemies do
- what environmental hazard escalates
- what clue becomes harder or easier to find

## Point Forward

Point Forward tells the DM how to move to the next scene.

Include:
- destination or next beat
- what success changes
- one alternate route or shortcut if present

## Fail Forward

Fail Forward must preserve momentum.

Include:
- what the party still learns
- what cost is paid
- how the next scene changes

Do not use "they fail and nothing happens."

## Handouts

If no specific handout exists, include:
- "None required"
- or "Optional: map scrap, clue note, symbol sketch, NPC note"

## Escalation

Every scene page needs an escalation mechanic.

Use generic pressure-step language that fits the adventure, not only the current packet's specific clocks.

Each major scene must include a small `Escalation Guide` with:

- what escalates pressure
- how much pressure increases
- 2-3 short examples tied to the scene
- what the party can do to reduce, prevent, or redirect escalation

Identify the scene's main pressure track: time, danger, suspicion, enemy readiness, environmental instability, morale, resource loss, pursuit, ritual progress, corruption, alarm, heat, exhaustion, or another adventure-specific pressure.

Use this reusable pattern:

```text
Escalation Guide:
If the party delays, fails a key check, makes loud choices, ignores a warning, rests in danger, or lets an enemy objective continue, increase pressure by 1 step.

Pressure Step Examples:
+1 Pressure: raise the next DC by 2, add a minor hazard, reduce a resource, worsen a clock/timer by 1, or give the enemy a small positional advantage.
+2 Pressure: add a minor enemy group, trigger a complication, split the party's attention, empower the next scene, or start the next scene with an active hazard.
+3 Pressure: advance the villain's plan, remove a safe option, start the next scene at disadvantage, trigger a major consequence, or force an immediate hard choice.

Reduce Pressure:
Clever planning, fast action, sacrifice, stealth, negotiation, rescuing someone, destroying a focus, spending a scarce resource, or accepting a meaningful cost can remove 1 pressure or prevent the next increase.
```

Keep examples short and table-ready. Do not write abstract advice only. The page must show exactly what the DM changes at the table.
